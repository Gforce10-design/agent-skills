# 영상 제작 도우미

사용자의 자연어 요청을 기존 로컬 도구로 실행한다. 명령어·상태 지문·파일 구조를 사용자에게 직접 조작하게 하지 말고, 결과와 필요한 결정만 쉬운 한국어로 전달한다.

## Claude·Codex 공통 사용

이 본문과 Python 명령은 특정 AI 클라이언트에 종속되지 않는다. Claude Code와 Codex가 `/Users/gimsuyeong/.agents/skills/video-production/`의 같은 원본을 읽는다. 현재 클라이언트가 제공하는 파일 읽기·편집·셸 도구로 실행하며 다른 클라이언트의 도구 이름이나 권한을 가정하지 않는다. `agents/openai.yaml`은 Codex 표시 정보일 뿐 실행에 필요하지 않다.

| 환경 | 호출 예 |
|---|---|
| Claude Code | `/video-production 지금 프로젝트의 상태와 다음 할 일을 알려줘.` |
| Codex | `$video-production 지금 프로젝트의 상태와 다음 할 일을 알려줘.` |
| 자연어 | “영상 제작 도우미로 지금 프로젝트의 상태와 다음 할 일을 알려줘.” |

작업 상태와 오너 기록은 프로젝트 파일에서 읽는다. 다른 클라이언트로 이어가도 현재 파일·버전을 다시 확인하며 같은 프로젝트를 동시에 수정하지 않는다. 스킬 사용을 위해 다른 모델이나 C2C 연결을 시작할 필요는 없다.

## 작업 대상과 도구

검증된 도구 저장소는 `/Users/gimsuyeong/Developer/claude-code-book`, 실행 파일은 그 아래 `marketing/templates/video/`에 있다. 다른 작업 폴더에서 시작했어도 **실행 파일은 이 절대 경로**, 입출력은 사용자가 지정한 경로를 쓴다. 해당 저장소가 없으면 같은 이름의 임의 파일을 실행하지 말고 실제 위치를 확인한다. 코드나 양식을 스킬 폴더에 복제하지 않는다.

- 프로젝트 명령을 쓸 때: [COMMANDS.md](/Users/gimsuyeong/Developer/claude-code-book/marketing/templates/video/COMMANDS.md)를 읽는다.
- 블록아웃·측정 자료를 만들 때: [BLOCKOUT-TOOLS.md](/Users/gimsuyeong/Developer/claude-code-book/marketing/templates/video/BLOCKOUT-TOOLS.md)를 읽는다.
- 자동화 범위가 불분명할 때: [TOOLING-ROADMAP.md](/Users/gimsuyeong/Developer/claude-code-book/marketing/templates/video/TOOLING-ROADMAP.md)에서 구현된 부분과 계획을 구분한다.

대화에서 진행 중인 프로젝트나 사용자가 지정한 경로를 우선한다. 여러 후보가 있고 대상이 분명하지 않을 때만 프로젝트를 묻는다. 새 프로젝트 이름이 없으면 이름 하나를 묻고, 길이·예산·스토리는 기획서 작성 과정에서 다룬다. 빈칸을 임의의 확정 사실로 채우지 않는다.

## 요청을 실행으로 연결하기

| 사용자의 말 | 실행할 일 |
|---|---|
| “새 영상 프로젝트 시작해” | 이름·경로를 확인해 `video_project.py new`. 기본 위치는 저장소의 `marketing/video-projects/<slug>/`. 이어서 `status`로 실제 생성 결과 확인 |
| “어디까지 됐어?”, “다음 할 일 알려줘” | 새 명령으로 만든 프로젝트는 `status --json`. 단계·누락·재확인·중단 여부를 해석하고 다음 미완료 작업 제시 |
| “기획서/콘티를 작성해” | 해당 단계 양식과 상위 문서를 읽고 초안 작성. 사용자가 모르는 내용은 미정 또는 제안으로 표시 |
| “이 문서를 확정해” | 대상이 명확한 실제 오너 발언을 보존하고 `lock`의 사전 점검→확정 실행. 아래 ‘확정·수정’ 규칙 적용 |
| “기획/공간/콘티를 수정해” | 잠긴 문서는 수정 전에 `revise`; 초안은 요청한 내용 편집. 영향받는 하위 문서와 다시 검토할 순서 보고 |
| “블록아웃 준비해” | 기하 구조가 담긴 입력으로 `blockout_tools.py prepare`. 명시적으로 로컬 3D 렌더도 요청했으면 `render`까지 수행 |
| “이 그림에 눈금 넣어”, “측정 양식 준비해” | `grid`, 또는 블록아웃·방향·원본 이미지가 연결된 `measure-init` |
| “중단된 변경 복구해” | `status`의 미완료 기록 확인 후 `recover`. 충돌 시 자동 덮어쓰기나 기록 삭제를 하지 않음 |

명령은 `python3 -B <실행 파일 절대 경로> ... --json`으로 호출한다. 요청 범위가 명확하면 사전 점검 뒤 허용된 로컬 실행까지 이어간다. `--dry-run`은 변경 내용을 검사하는 수단이며 그 자체가 추가 승인 질문의 이유는 아니다. 사용자가 준비·계획·점검만 요청했다면 실제 생성·확정·렌더로 넓히지 않는다.

## 확정·수정에서 지킬 것

- `status`가 반환한 현재 `revision`을 `--expected-state`에 전달한다. 내용 편집 후에는 새 상태를 다시 읽는다. 충돌이 나면 실제 차이를 살피고, 무조건 새 지문을 가져와 재시도하지 않는다.
- `lock`에는 실제 오너 원문 파일, 확정 범위, 발언 출처를 전달한다. 대화에서 받은 원문은 새 작업용 텍스트 파일에 그대로 기록할 수 있지만 발언·메시지 ID·수락을 만들면 안 된다. 출처 ID를 모르면 현재 대화와 원문 등 확인 가능한 정보로 명시한다.
- 대상과 범위가 분명한 확정 발언은 같은 내용을 다시 묻지 않는다. “좋다/맞다”가 무엇을 확인한 것인지 불분명하면 대상만 확인한다. 참조 확인·문서 확정·클립 수락·생성 지시는 서로 대신할 수 없다.
- 일반 `lock/revise`는 00~04, 장면별 05, 06, 09단계 문서만 지원한다. 07단계 생성 지시, 08단계 수락, 10단계 최종 수락을 이 명령으로 처리하지 않는다.
- `revise`는 버전을 열고 관련 문서를 `needs_recheck`로 표시한다. 이후 본문과 `based_on`을 실제 검토 결과에 맞춰 고친다. 이전 오너 수락을 새 버전에 복사하거나 참조 버전만 올려 재검토를 끝냈다고 하지 않는다.
- `status` 종료 0은 조회 성공이다. `issues`·`pending_transactions`와 실제 단계 상태를 함께 읽는다. 내용 검사에는 `check_templates.py --project <경로>` 또는 대상 `lock --dry-run`을 쓴다.

## 블록아웃·측정에서 지킬 것

- 출력은 사용자가 지정한 **새 검토 폴더**를 쓴다. 지정이 없으면 저장소 `ops/video-prep/<프로젝트>-<고유 작업 이름>/` 아래 새 폴더를 준비한다. 입력·기존 출력·확정 파일을 덮어쓰지 않는다.
- 첫 버전은 회전 없는 상자·수직 원기둥, 카메라 roll=0·가로 눌림 없음만 지원한다. 지원 밖의 회전을 0으로 바꾸거나 물건을 빼서 실행하지 않는다.
- 기준점 후보는 계산 제안이다. 실제 표면에서 보이고 식별 가능한지 검토하기 전 원본 기준점에 자동 반영하거나 오너 수락으로 기록하지 않는다.
- `measure-init`의 `--image`는 눈금 없는 원본이다. 관찰값 `output`은 미측정이면 `[null,null]`, 맞음 수와 잰 축은 0으로 둔다. 계산값 `render`를 관찰값에 복사하지 않는다. 독립 출력 폴더는 `check_templates.py --project`의 대상이 아니므로 원본 해시·행 수·미측정 값을 확인한다. 프로젝트에 참조를 연결해 검사할 때 빈 기록의 “잰 축 없음” 실패는 정상이다.
- 오너가 실제 결과를 보고 한 판정만 `owner_review`와 피드백에 기록한다. 기존 95%·물체별 판정·허용 오차를 통과시키려고 바꾸지 않는다.
- 실제 렌더의 크기·종료 코드·비교점 수와 카메라별 검증 여부를 읽는다. 준비 성공, Blender 렌더 성공, 실제 이미지 측정, 오너 수락은 구분해서 보고한다.

## 기존 자산과 현재 실행 경계

B02는 새 프로젝트 명령 이전의 구조다. B02 요청이면 먼저 [CURRENT-ACCEPTED.md](/Users/gimsuyeong/Developer/claude-code-book/marketing/video-projects/b02/CURRENT-ACCEPTED.md)의 최신 항목과 해당 해시를 확인한다. B02나 수동 복사 프로젝트에 새 명령의 관리 표식을 만들거나 변환하지 않는다. 지원되지 않는 프로젝트의 현황은 기존 상태·수락 기록을 읽어 보고하며, 실패한 `status` 대신 관리 데이터를 새로 만들지 않는다.

이 스킬의 명령은 로컬 준비 기능이다. 유료 생성·업로드·게시·commit/push·C2C 연결 변경·생성 차단 장치 변경을 일반적인 “진행해/확정해/준비해”에서 추론하지 않는다. 현재 대화의 금지를 유지한다. 새로운 명시 지시가 있더라도 미구현 기능을 완료한 것처럼 처리하거나 기존 차단 장치를 우회하지 않는다. 실제 참조 이미지 선택은 오너 확인이 필요하다. 이미지 신규 제작 경로는 기존 절차의 ChatGPT 구독 웹 원칙을 따르며 이 로컬 스킬이 대신 제출하지 않는다.

## 사용자에게 보여 줄 것

“무슨 상태/문제인가 → 무엇을 했나 → 다음 작업이나 필요한 결정” 순서로 짧게 보고한다. 결과물·검증 기록은 클릭할 수 있는 경로로 준다. 구현되지 않은 다음 기능과 현재 작업의 완료를 구분하고, 사용자가 결정해야 할 내용만 묻는다.

위 호출 접두어 뒤에 붙일 요청 예:

- `새 영상 프로젝트 demo-ad를 시작해 줘.`
- `지금 프로젝트는 어디까지 됐는지 알려줘.`
- `이 블록아웃 파일로 배치도와 기준점 후보만 준비해 줘.`
- `이 원본 이미지와 블록아웃으로 눈금·빈 측정 기록을 준비해 줘.`
